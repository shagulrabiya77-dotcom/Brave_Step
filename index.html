BRAVE STEP 2.0 / INNOVATION PRESENTATION
01 / THE VISION

Not just a device.
A step towards independence.

Brave Step 2.0 explores how affordable electronics and a simple mobile interface can work together to make everyday activities more accessible.

The project is built around one central idea: assistive technology should be understandable, practical and designed with the user. Instead of treating mobility, communication and emergency support as unrelated needs, Brave Step brings them into one proposed support ecosystem.

It is a prototype-stage innovation. Its purpose is to demonstrate a possible approach, identify engineering challenges and create a foundation for user testing and future development.

Our guiding principle

Build technology that helps people navigate their environment, express their needs and reach support with greater confidence.

03 / THE PROPOSED SOLUTION

One ecosystem.
Three support pathways.

The website presents the intended system architecture. Each pathway can be developed and tested independently before integration.

⌁01 / MOBILITY
BRAVE STEP · SMART STICK CONCEPT

Awareness while moving

A microcontroller-based prototype can read nearby obstacle and water-sensor signals. The system can translate sensor readings into distinct alert patterns so that the user receives information without needing to look at a screen.

  • Obstacle detection using suitable distance sensors
  • Water-level or wet-surface detection using a water sensor
  • Different buzzer or vibration patterns for different alert levels
PROTOTYPE COMPONENTS · TESTING REQUIRED
◎02 / COMMUNICATION
BRAVE STEP · MOBILE APP CONCEPT

Information in an accessible format

The mobile application is planned as a simple control and information layer. It can present system status, provide voice guidance where supported and offer quick communication choices.

  • Clear, large controls and a simplified interface
  • Optional text-to-speech guidance using the device's supported voice
  • Pre-written assistance messages for quick communication
APP FEATURES · DEVICE COMPATIBILITY VARIES
✳03 / EMERGENCY
BRAVE STEP · SOS SUPPORT CONCEPT

A clearer route to trusted contacts

With user permission and a working phone connection, an SOS workflow can prepare an emergency message and share the phone's available location with selected trusted contacts.

  • Pre-selected emergency contacts
  • Location sharing subject to permissions and GPS/network availability
  • Optional phone flashlight alert, subject to device support

InterfaceLarge, clear controls

Engineering honesty: A sensor does not understand a scene. It only measures a particular physical signal. Sensor placement, calibration, false alerts, battery life, weather resistance and user trials must be evaluated before claiming dependable real-world performance.

06 / IMPACT & VALIDATION

Innovation must be
measured, not assumed.

A successful assistive product is not defined only by the number of features. It is defined by whether people can use it safely, comfortably and consistently.

Brave Step's next stage should involve feedback from people with disabilities, caregivers and accessibility specialists. Their input should guide the interface, alert patterns, physical design and priorities.

Proposed evaluation plan

01

Functionality testingCheck sensor readings, alerts, app permissions and connection reliability.

02

Accessibility reviewEvaluate readability, audio clarity, alert distinction and ease of interaction.

03

Safety assessmentIdentify false negatives, false alerts, battery failure and fallback needs.

04

Guided user trialsRun supervised, consent-based trials in controlled environments.
